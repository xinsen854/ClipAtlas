# 自动粗剪匹配规则 P0

这些规则由软件执行，适用于新文案；不包含特定文案到素材文件、视频 ID 或时间段的映射。
项目的素材范围和规则偏好仍通过现有入口读取。

## 固定素材范围内的自动调度

素材匹配不足时自动调整，不把“增加素材”当作正常工作流的前提。所有阶段沿用同一素材范围，
指定 video_ids 时不会借用未选中的视频；全部素材模式只使用当前本地素材库。

1. 精确需求和原备选查询优先；必要时允许至少约 1 秒的完整短镜头参与分配，不用长段落的零点几秒尾巴凑数。
2. 不足时自动改为预先规划的同主体使用、体验或展示场景，并标记“自动辅助配图”。它不证明原文的具体功能。
3. 仍不足时，从当前范围内已召回的素材、再从同一范围的未用场景安排补位，标记“库内兜底，未验证匹配”。
   这类条目没有 AI 匹配分数或新画面描述，不写入 catalog_annotations，也不生成假语义索引。
4. 只有选定范围可用的唯一时长确实不足时，才补足必要的复用量，标记“受控复用”；不会在候选用完时无限循环。

普通镜头仍采用默认节奏，自动调度才允许短镜头例外。文件不存在、没有有效视频时长、模型服务故障等技术问题仍会如实报错。
这项调度优先排除已用源时间范围；跨文件、带不同包装的同画面检测尚未由这项改动解决。

## 全文规划与证据检索

短文案在真实时间对齐后，用一次模型请求规划全文画面段落。长文案每 40 个单元分批规划，
不是每句话重新请求意图模型。软件保存主体、表达目的、证据来源、匹配类型、画面查询、短关键词和备选画面。
模型只能合并相邻且同一画面意思的单元（合并最多 16 秒）；覆盖检查确保不漏句、不重排。
原文和时间边界由程序从输入复制，不接受模型改写。规划失败会提示，不静默恢复慢速逐句试搜。

- **Visual** 用画面语义召回动作、对象、外观、场景。首轮一个画面查询；不足时使用预先规划的备选查询。
- **ASR** 用短关键词召回说话、采访、引用相关内容。原话命中不代表画面展示了原话中的动作。
- **OCR** 用短关键词召回配置名、标签、参数等。屏幕文字命中不代表已经验证某项功能。
- **排名融合** 使用 RRF（常数 60），主要证据通道权重 2，其余权重 1；同一通道多个同义词不重复累加票数。
  不直接比较余弦相似度与文本包含分数。此路径仅供新全文规划的粗剪使用，普通 Hybrid 搜索入口保持原行为。
- **辅助配图** 用于抽象过渡、评价、定位，允许相关的日常使用、主体展示和事件场景。
  它不证明具体技术事实；具体功能和行为属于“具体内容匹配”，仍需看图确认。
- **少量复核** 已规划段落每轮通常最多复核 4 个辅助候选或 6 个具体候选，较长段落按所需镜头数留足候选。
  有上限地补搜一次，满足内容与节奏就停止。没有把未经复核的向量包装成自然语言标注。
- **减少重复读取** 单次向量检索按 video_id 复用视频元数据，避免每个向量重新开库查视频。

结果页展示软件规划的表达目的与“辅助配图/具体内容匹配”。它们表示选材用途，不是人工确认标记。
当前运行条目不能在服务重启后从候选中途续跑，已完成条目和已保存的旁白对齐修订保留。

1. **按真实旁白时间选材。** 真人旁白先由现有 ASR 识别，程序把原文案与词时间对齐，再形成有时间的内容段。未读标题单独提示；不平均分配时间，不把整篇当成一个候选池循环填充。
2. **保留上下文，检索当前内容。** 全文背景用于确认主体、类型和代词。当前段落自动转换成可见的对象、动作或场景；不把修辞、参数声明变成并不存在的测试事件，也不因为提及人物就只找人物讲话。
3. **不同意图分别召回。** 软件生成画面查询并调用已有 Hybrid；多路候选交错保留，避免仅以不同查询的原始分数统一挤掉某种画面。普通 Hybrid 搜索接口不变。
4. **按实际画面复核。** 现有看图模型判断候选是否能说明当前画面需求。功能细节优先实际展示、操作、清楚的图解；纯 Logo、文字尾板、无关讲话不充当功能镜头。抽象的开场、定位或总结允许相关的现场和主体展示。不把无法辨认的具体型号、能力或身份当成已证实事实。
5. **使用已有镜头边界。** 向量命中区间是召回线索，不是必须照搬的剪辑长度。软件可在同一已知场景内寻找较长的连续范围，并重新看图复核整个范围；不得越过原片切点拼成假长镜头。同一视频的已用时间范围不能再次选用；这个检查不等同于跨文件的画面相似去重。
6. **候选不足自动调度。** 精确补搜和同主体配图均有次数上限，单个候选格式无效可跳过。仍不足时按上述固定库补位规则处理，明确显示匹配的局限。
7. **保留可检查的结果。** 每段保存文案、成片时间、实际素材范围和模型选用理由。候选相关性低于 0.65 不采用；0.65 至 0.8 在检查页标为近似匹配。模型评分不是人工确认，具体型号和技术特性仍需结合画面复核。

## 通用镜头节奏规则

适用于讲述、介绍、知识说明等解说型内容，不按某篇文案、车型、文件名或素材 ID 特判。

- **默认以 5.5 秒为目标。** 通常形成约 4–7 秒的镜头，普通独立镜头至少 3 秒、最多 8 秒；1.5–3 秒仅保留给确实很短的 S 级动作证据（由导演分级标记）。时长是编排依据，不降低画面匹配要求。
- **先确定镜头数量，再分配整段时间。** 在可用连续长度内，优先选接近目标节奏的数量，再均衡分配时长。5.335 秒不能用 5 秒加 0.335 秒凑出，也不允许低于 3 秒的段；有足够长的素材时用一镜覆盖，否则诚实提示缺素材。
- **长而相关的连续画面优先。** 不因为某个一秒片段分数稍高，就用多个短片段代替能完整覆盖内容的相关镜头。缺少长镜头时按自动调度规则开放短镜头例外；不冻结、不慢放来伪造时长。
- **文案单位与镜头单位分开。** 对齐得到的原句时间保留。逗号连接的句内延续内容，合并后不超过 8 秒时，可共用一个讲述单元；句末和较长内容边界继续保留。不能仅为了减少时间轴小块，拼接不连续或不相关画面。
- **短独立内容是例外，短尾巴不是。** 一个独立讲述单元本身不足 3 秒时，允许用一个镜头完整覆盖；不能把一个正常长度的段落拆成多个不足 3 秒的碎片。
- **补搜也遵守同一节奏。** 候选总秒数够，不代表能够合理分配；软件同时检查最短镜头和可用连续长度，再决定是否继续补搜。

目标是让观众看清画面，每分钟大约 10–13 个镜头可作为默认节奏参考，不是强制数量配额。
具体结果仍受文案内容边界和原素材连续长度影响。

## 执行位置

- `clipatlas/speech/narration_alignment.py`：真实音频对齐和标题提示。
- `clipatlas/roughcut/beats.py`、`planner.py`：分段、范围去重、生成与保存；planner 读取 director 分级（S 级 DIRECT 优先、avoid 硬过滤、纯 B 段并入前镜）。
- `clipatlas/roughcut/pacing.py`：通用时长、镜头数量及均衡分配规则；编排与候选复核共用。
- `clipatlas/retrieval/intent.py`、`intent_search.py`：软件自动生成检索词、保留上下文和补搜词。
- `clipatlas/retrieval/storyboard.py`：全文画面规划结构、顺序和覆盖校验。
- `clipatlas/retrieval/local_rough_cut.py`：本地召回与 annotation 直读（素材入库时一次性标注，剪辑阶段零 API）。
- `clipatlas/director/`：文案定稿时一次 API 做 S/A/B 分级（analyzer），按（文案哈希+prompt 版本+规则版本）永久缓存（store），本地 DIRECT/SUPPORT/REJECT/UNKNOWN 判定（local_fit）；其余链路不调用 API。
- `clipatlas/providers/qwen.py`：素材入库的看图标注与结构化输出（不再做 DeepPass 式逐候选复核）。
- `clipatlas/providers/openai_compat.py`、`zhipu.py`、`deepseek.py`：智谱 GLM-4.1V / DeepSeek V4-Flash-Vision 的 OpenAI 兼容适配器，供素材入库标注替换成本模型。

## 样本文案的测试方式

通过与页面相同的 API，提交原文案和原音频到 `/api/v1/narration/import`，
再向 `/api/v1/rough-cut/plans` 只提交项目 ID 和 Top-K。
软件自行对齐、检索、筛选、编排；随后将返回的 plan_id 提交到 `/api/v1/exports/jianying` 导出。

测试请求不传预选视频、逐句检索词、候选列表、镜头时间段或人工编排结果。
验收读取软件输出及日志，不修改已选镜头。原音频、旧草稿与素材索引保留。

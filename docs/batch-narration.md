# 批量 MD 文案与真人旁白

入口：文案与旁白 → 批量MD与真人旁白。

推荐每条文案有固定编号，音频文件名保留同一编号：

```markdown
# 本批文案

## 001 发布会
这里是第001条完整旁白文案。

## 002 越野演示
这里是第002条完整旁白文案。
```

对应音频为 `001_发布会.wav`、`002_越野演示.mp3`。文件选择顺序不影响编号匹配。

- 一个批次最多100条。支持以下文案边界：
  - Markdown 标题：常用 `## 001 标题`；多个 `#` 时按一级标题拆，其他标题层级沿用最浅层级。
  - 顶层数字编号：`1. 标题`、`1、标题`、`1) 标题`、`（1）标题`、`【1】标题`，以及全角数字、转义的 `1\.`。
  - 顶层中文编号：`一、标题`、`（一）标题`；或 `文案1：标题`、`文案一：标题`、`第1条：标题`、`第一篇：标题`。标签与标题之间使用空格或冒号，也可让标签独占一行。
  - 分隔线：没有条目标题时可用单独一行 `---`、`***`、`___` 分隔正文。
- 数字编号需要出现至少两个同级条目，并从文档开头开始，或位于单个 Markdown 合集标题之下。正文前已有普通段落时，不把其后的编号清单直接当作文案合集；正文内部的小编号应缩进。
- 普通换行、空行、句号、价格小数不会单独拆分，代码围栏内部的标记也不参与拆分。已有明确的 Markdown 多条目标题或分隔线优先。
- 标题下一行有正文时提取正文；整条只有一行，或编号行已经包含长正文/完整句子时，编号后的内容完整保留在该条正文内，避免误删。例如本次提供的 `1.`、`2.`、`3.` 三条长文会拆成3条，第三条标题与正文同一行也不会丢失内容。
- 没有编号时，尝试唯一标题、唯一首段或至少12字的首段开头匹配。编号冲突、重复候选、一个音频匹配多条文案都不会自动分配，需手动选择。
- 配对预览只读取MD与文件名/大小，不上传音频、不调用AI。匹配不能验证音频实际读了哪些内容，确认前需要用户核对。
- 确认配对后逐个导入音频。每条文案单独保存音频、实际时长和旁白ID，当前单条文案/激活旁白保持原样。
- 导入后可再次确认，串行生成已就绪条目的粗剪；此步骤调用已配置的AI。所有条目复用共享素材索引和项目规则，不会重新解析整个素材库。处理期间请保持本页打开。
- 停止或离开页面会停止发起后续条目，当前请求完成后保存结果。回来后选“已保存批次”；未导入条目需重新选择原文件，已导入音频无需重复上传。
- 旁白与粗剪使用批次/条目对应的固定ID，重试会跳过已完成结果。配对确认后不可静默换文件；修改正文、文件名或大小需要重新建立批次。
- 每条粗剪可在新标签打开结果与导出。默认草稿名称包含方案ID，避免同一项目的不同条目同名。

批次记录保存在现有旁白数据库的`narration_batches`表。没有新增后台队列或自动启动的批量任务；每个导入/粗剪请求由页面依次发起。

# 素材解析与续跑

素材间仍按队列逐个处理。单个素材准备完成后，Visual、ASR、OCR 同时推进；每一路使用有限任务数，并及时保存分段结果。旧场景准备、模型、切片粒度、向量维数、OCR 采样和 Hybrid 算法保持原样。

默认配置见 `.env.example`：Visual API 并发 4、ASR 3、OCR 6，素材库 FFmpeg 共享并发 1。每路最多额外准备一个输入，网络等待不占用 FFmpeg 额度。可通过 `CLIPATLAS_*_CONCURRENCY` 调整；机械硬盘先用默认值。

请求平滑限速默认 Visual 180 RPM、ASR 60 RPM、OCR 240 RPM，低于官方公布上限。不同模型独立计量，同一主账号还会合并其他应用流量并受 Token、秒级和突发保护限制；收到限流时有限次退避，每次重试重新过限速器。Visual 调度在 ClipAtlas 适配层实现，SentrySearch 原始文件不变。

- 启动服务后解析默认暂停，扫描不会自动开始调用模型。
- “继续未完成”处理排队素材；失败素材先点“重试”重新排队。已有成功片段会跳过，ASR/OCR 沿用当前 revision。
- “全部重新解析”明确确认后强制重跑，ASR/OCR 为新一轮分配新 revision。
- “清空解析结果与缓存”是全局共享素材库操作，弹窗说明范围，清空后保持暂停。
- 暂停后台处理会完成当前素材再停止。页面发起的批量重新解析使用自己的“完成当前素材后停止”，不要把二者混用。
- 一路失败不会阻断另外两路收尾。整条素材仍标记失败，供下一次补齐缺口；失败或退出时不丢下仍写库的任务。

详情返回 `processing_stages`，同时显示各路状态；旧 `processing_stage` 兼容保留。结果仍分页，处理中也可查看已经保存的实际 ASR/OCR。Visual 展示向量元数据，不生成自然语言画面标注。

配置修改需重新加载服务。在切换前等待当前请求收尾，在线备份数据库，切换后先核对 checkpoint，再恢复；不得以清空缓存或强制全量重跑代替续跑。

运行日志使用标准 `clipatlas.*` logger，记录分段耗时、FFmpeg 排队/执行、接口等待/重试和各阶段总耗时；接口耗时包含上传、网络及服务端处理，不等于纯推理耗时。

本轮不启用跨视频预准备、GPU 编码、SSD 迁移或新队列系统。这些优化需在当前版本实测后独立评估。
